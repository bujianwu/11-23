4.部署的时候可能会丢数据或者服务器宕机，咋解决

用主从复制（最好 MGR 强一致）保证服务不中断——因为单台服务器宕机是必然的，多节点冗余才能让故障时自动切换、业务不停；用半同步或组复制保证数据不丢——因为异步复制下主库宕机时还没同步到从库的数据会永久丢失，必须让事务提交依赖多节点确认；再异地备份兜住最坏情况——因为再强的冗余也怕误删库或整个机房断电，备份是最后的底线。

6.介绍一下多智能体协作和工作流

工作流：把复杂任务拆成有明确依赖关系的固定步骤，用 DAG 预先定义好每一步做什么、上一步输出怎么传给下一步、失败了怎么重试，核心是用确定性换取可预测、可审计、易调试，适合流程能事先画出来的场景。
多智能体协作：给多个 Agent 各自设定角色、工具和目标，让它们自己决定怎么完成任务、怎么跟其他 Agent 沟通协调，核心是用自主性换取灵活性，适合流程画不出来、需要临场判断的开放式任务。

主管-工作者：一个主管 Agent 拆任务、派活、汇总，工作者只管执行，适合任务能清晰分解的场景。
流水线：多个 Agent 串行接力，每个负责一个环节，输出传给下一个，适合有天然阶段划分的任务。
群聊：所有 Agent 在一个共享对话里按规则轮流发言，共同推进任务，适合需要多方讨论的开放性问题。
层级：主管下面还有子主管，多层分解任务，适合规模大、需要逐层拆解的场景。
去中心化：没有中心主管，所有 Agent 平等自由通信、互相协商，适合需要高度自治的场景。
辩论：多个 Agent 对同一问题各给答案、互相质疑，最后投票收敛，适合需要多角度验证的场景。
投票：多个 Agent 独立完成、对结果投票取多数，适合有明确对错、需要提高可靠性的任务。
反思：一个 Agent 生成、另一个批评修正，反复迭代，适合需要高质量输出的场景。
